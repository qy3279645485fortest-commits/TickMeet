# 图片存储实施与验收

## 当前实现

StorageService分离业务与存储；LocalStorage提供受控目录、临时文件写入后原子移动；S3Storage通过固定版本MinIO Java SDK 8.5.17访问S3兼容API，不等于部署了MinIO服务器。

流程：身份/用途/限流 → 最大5MiB → JPEG/PNG魔数、MIME与ImageIO解码 → 2000万像素上限 → 重编码 → UPLOADING台账 → 存储写入 → READY。客户端原始文件名不参与存储路径。

台账记录owner、purpose、provider、namespace（S3为bucket）、objectKey、类型、大小和状态。URL为/api/files/{id}/content，由后端读取，不暴露存储凭据；票码不进入公开图片系统。

绑定检查同文件行锁、READY、归属和用途。活动/场馆/笔记业务记录与引用同事务。已引用文件拒绝删除。删除先DELETING，提交后调用存储；成功200，失败202。后台每分钟重试DELETING，并清理超过10分钟未完成的UPLOADING。

切换provider/bucket后，旧台账的存储位置不匹配会返回明确错误，防止在新桶误删同名对象。切换配置不是自动数据迁移。

## 已通过测试

- 伪装成.jpg的脚本被拒绝。
- 有效PNG上传/读取，本人删除幂等，他人删除403。
- 被引用文件拒绝删除，未调用存储删除。
- 模拟上传超时：保留UPLOADING，补偿清理后DELETED。
- 模拟删除超时：返回待处理，重试后DELETED。
- 上述失败注入通过Mock StorageService执行；本地真实文件路径另有测试。

## S3实验配置

设置SPRING_PROFILES_INCLUDE=s3并提供.env.example中的S3参数。bucket需事先创建，后端账号只授予该bucket的对象读写/删除权限；不要公开桶列表或凭据。

尚未连接真实S3/MinIO服务器，也未执行跨实例读写、服务端故障、备份恢复测试。当前报告不声称这些验收通过。
