## 浏览器已实际验证

观众登录 → 选择早鸟票 → 异步建单 → 模拟支付 → 电子票二维码 → 切换核销员 → 核销成功 → 重复核销提示“此票已经核销，请勿重复放行”。

前端提供发现/搜索、附近场馆、订单/退款、票夹、社区/关注动态/个人记录、签到、运营创建发布暂停、核销员页面。前端使用后端API，无伪造订单静态数据。

补充浏览器验证：运营创建“TickMeet 现场体验专场”（12张票）→ 草稿 → 发布成功。已检查窄屏布局，无横向溢出。

## 发现并修复的问题

- 运营表单createEvent与浏览器内置同名方法冲突：重命名submitNewEvent，创建/发布实测通过。
- PowerShell新版本JSON时间自动转换导致旧进程识别失败：统一比较UTC ticks并等待进程退出，重启已验证。
- Spring事务代理对象的字段访问导致目录测试空指针：改为通过服务方法取Db。
- HTTP缺少幂等请求头误映射为503：增加400参数错误处理，并有回归测试。
- 预占与超时回收竞争：请求行锁覆盖准入过程。
- Redis冷库存并发初始化：改为发布前预热；丢键拒绝抢票。
- 订单暂停与正在准备的请求：准备阶段锁票档并读取最新售卖状态。
- 测试/体验消费者同队列：live测试独立使用tickmeet-test/tickmeet-recovery-test队列前缀。
- 回调内容摘要从普通hashCode改SHA-256。
- 权限拦截失败的ThreadLocal清理、前端失效token清理。
- 文件存储半成功：台账状态与定时清理/删除重试；provider/namespace检查。

## 验证边界

真实Redis测试是单节点；恢复测试是维护窗口，不是Sentinel切主。S3适配器已编译，真实对象服务器未验收。SMTP未测试实际送达。未进行生产容量、Grafana告警触发、HTTPS或多实例全局恢复演练。

与规划的具体差异见API与规划差异.md。源码中的demo与live适配器分开，README明确说明，不能把demo模拟器描述成真实Redis/MQ。
