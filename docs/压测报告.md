# 并发正确性验证与压测边界

日期：2026-09-17。测试在本机Windows JVM，真实中间件在同机WSL Ubuntu，存在共享CPU/IO和网络转发开销。

## 已执行

| 场景 | 参数 | 结果 |
|---|---|---|
| 本地适配器并发抢票 | 40唯一请求、12工作线程、库存8 | 仅8订单，DB库存0 |
| 真实Redis Lua + MySQL + RabbitMQ | 30唯一请求、12工作线程、库存5 | 仅5受理成功并最终建成5订单；DB/Redis均0 |
| 并发核销 | 6线程核销同一张票 | 仅1次VERIFIED、仅1条核销记录 |
| 重复消息/请求 | 同幂等key、重复createOrder/释放 | 1订单；旧释放不影响新占用 |
| 故障恢复 | 5张票、1已建单+1待建单、删除测试库存键 | 保留预占后重建，重复释放不加库存 |

原始证据见docs/test-evidence下的Surefire摘要。结果只证明这些负载下业务不变量成立。

## 未测量，不填写虚构数值

未做JMeter长稳态HTTP压测；没有可引用的生产QPS、P95/P99、数据库瓶颈结论，也没有三轮相同硬件的性能对比。JUnit方法耗时不能当接口响应P95。

后续容量实验需分别准备100张稀缺票与充足库存，每个虚拟用户独立token、每次新购买独立幂等key，并采集：

- MySQL锁等待/连接池、Redis延迟、MQ积压与Outbox年龄；
